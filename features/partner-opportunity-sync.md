# Partner Opportunity Sync

Two-way, token-authenticated sync of shared opportunities and their solicitation documents between this app and the partner capture platform, so records and attachments are no longer re-entered by hand on both sides.

**Status:** `planned`
**Branch:** `feature/partner-opportunity-sync`
**Scope of this spec:** the E-Logic-side work that does not depend on the partner's field list / sample payload. Items still blocked on the partner are listed under *Open items*.

## How it works (plain terms)

- Each side exposes one authenticated endpoint that returns its **shared** opportunities and shared files, readable only with a token issued to the other party.
- When something changes, the changed side sends a **light webhook** ("opportunity X changed"); the receiver **fetches** the record and applies it.
- A **changed-since pull** is the catch-up path if a webhook is missed. It includes removals.
- Records match on the **solicitation number**. After the first match the link is pinned to the partner's internal record ID.
- If both sides edit the same record, **the latest save wins** (UTC timestamp of the last save of the shared fields).

## User flow

### A. Opportunity created on the partner's side
1. Partner specialist creates it and flags it "Share with E-Logic".
2. Partner webhook hits `POST api/partner/webhook` (signature + timestamp verified).
3. We fetch the record (and file list) from the partner endpoint with our token.
4. Normalize the solicitation number and look for a non-deleted quote with the same key:
   - none, but an existing quote with no Solicitation # has a Code (`email_code`) equal to it (normalized) → hold for review under *Needs review* until the admin picks *Link to quote #N* or *Create new*;
   - none → create a quote: creator = *Partner Integration* service user; designated user = quote assignee matched by email against `usuarios.email`, else the default assignee (`PARTNER_DEFAULT_ASSIGNEE_EMAIL`) with `partner_needs_assignment = 1`; `share_with_partner = 1`; pin `partner_record_id`.
   - exactly one → link it (pin `partner_record_id`, set `share_with_partner = 1`), apply shared fields only. No duplicate.
   - more than one → do not link; list under *Needs review* in admin settings.
5. Download the partner's shared files into `documentos/{id}/` and register them in `partner_documents`.
6. Audit event `partner_sync_in` (or `partner_link`).

### B. Opportunity created on our side
1. User fills the Solicitation # and turns on **Share with partner** (New Quote, or Information drawer later).
2. Optionally ticks **Share** on individual files in the Documents drawer.
3. The change enqueues one outbound webhook; the cron dispatcher sends it.
4. Partner fetches from our endpoint and creates or links on its side.

### C. Edits and amendments
Either side saves a shared field or shared file → a notice is sent → the other side fetches and applies. Applying an incoming change never sends a notice back (no echo).

### D. Removals
- We stop sharing, or delete a shared quote → tombstone: appears in changed-since results with `removed: true` and a `removed` webhook is sent.
- Partner stops sharing / sends `removed` → we detach the link and stop syncing. The quote is **hidden only if it is still untouched** (status Created, never priced). A priced, submitted or awarded quote stays visible, just unlinked.

### E. Missed notices
Cron pulls `changed_since=<last_pull_at>` from the partner every 15 minutes and applies anything not already applied. Partner can do the same against our endpoint.

### F. Conflicts
Incoming change with `shared_updated_at` ≤ our `partner_shared_updated_at` → ignored. Newer → applied (and our timestamp is set to theirs, so it does not look newer than it is).

### G. Existing quotes at launch
No up-front match report and no bulk list is requested from the partner. Quotes start linking from the release date: existing quotes keep an empty Solicitation # and stay unlinked unless the user types one (then they match exactly, like any new quote). The only safety net is flow A step 4: an incoming record that equals an existing unkeyed quote's Code is held for one-click review instead of creating a duplicate.

## Data model changes

New migration `sql/partner_opportunity_sync_migration.sql` (idempotent, `INFORMATION_SCHEMA` guard pattern like the others; add to DEPLOYMENT.md).

**`rfq`** (additive only):
| Column | Type | Purpose |
|---|---|---|
| `share_with_partner` | TINYINT(1) NOT NULL DEFAULT 0 | sole sharing gate |
| `solicitation_number` | VARCHAR(255) NULL | as typed/received |
| `solicitation_key` | VARCHAR(255) NULL, indexed | trim + uppercase + collapse spaces |
| `partner_record_id` | VARCHAR(100) NULL, indexed | pinned partner internal ID |
| `partner_linked_at` | DATETIME NULL | |
| `partner_shared_updated_at` | DATETIME NULL (UTC) | last save of **shared fields** only |
| `partner_payload_hash` | CHAR(64) NULL | hash of last exchanged shared payload; detects real changes, suppresses echo |
| `partner_removed_at` | DATETIME NULL | tombstone marker |
| `partner_needs_assignment` | TINYINT(1) NOT NULL DEFAULT 0 | fallback assignee used |

**New tables**
- `partner_documents` — `id`, `id_rfq`, `file_name`, `shared`, `partner_file_id`, `size_bytes`, `sha256`, `shared_updated_at`, `removed_at`; unique `(id_rfq, file_name)`. Rows appear lazily for existing files (shared = 0).
- `partner_webhook_outbox` — `id`, `id_rfq`, `event`, `payload`, `attempts`, `next_attempt_at`, `delivered_at`, `failed_at`, `last_error`, `created_at`.
- `partner_integration` (single row, same idea as `notification_mailbox`) — `enabled`, `issued_token_hash`, `token_created_at`, `token_last_used_at`, `partner_base_url`, `partner_token`, `partner_webhook_url`, `signing_secret`, `last_pull_at`.

**Seed:** one non-login *Partner Integration* user in `usuarios` (unusable password), used as `id_usuario` on incoming quotes.

**Config constant** in `app/Bootstrap/config.inc.php`: `PARTNER_DEFAULT_ASSIGNEE_EMAIL` (set to the product owner's login email at build; must exist in `usuarios`).

## API surface (provisional until payload is agreed)

Routes added in `app/Bootstrap/routes.inc.php` + a new `api` `case` in `index.php`. All require `Authorization: Bearer <token>`; constant-time compare against the hashed token; failures return a bare `401`.

| Method | Path | Purpose |
|---|---|---|
| GET | `api/partner/opportunities?changed_since=&cursor=` | shared opportunities changed after the UTC timestamp, incl. `removed: true` tombstones; paginated |
| GET | `api/partner/opportunities/{solicitation_number}` | one shared opportunity + file list |
| GET | `api/partner/files/{file_id}` | authenticated download of a shared file |
| POST | `api/partner/webhook` | inbound light notice; HMAC-SHA256 `X-Signature` + `X-Timestamp`, rejected if older than 5 minutes |

File entries expose `id`, `name`, `size`, `sha256`, `updated_at`, `download_url`.

Outbound: `scripts/cron/partner_webhook_dispatch.php` (every minute, retry back-off 1m / 5m / 30m / 2h / 12h, then `failed_at`) and `scripts/cron/partner_pull.php` (every 15 minutes, changed-since).

## Acceptance criteria

1. Missing, wrong or revoked token → `401`, nothing leaked; valid token → `200`.
2. Only quotes with `share_with_partner = 1` and `deleted = 0` are returned; enabling sharing without a Solicitation # is rejected on New Quote and the Information drawer.
3. Only files with `shared = 1` are listed or downloadable; app-generated files can never be marked shared (server-enforced); a non-shared file ID returns `404`.
4. `changed_since` returns changed and removed records, stable order, paginated; a record removed (unshared or deleted) appears with `removed: true` indefinitely.
5. Webhook with a bad signature or stale timestamp → `401`, no data change.
6. Incoming new record creates one quote with the *Partner Integration* creator, matched or default assignee, `share_with_partner = 1`, pinned `partner_record_id`, and an audit event.
7. Incoming record matching exactly one existing quote links it and updates shared fields only; no duplicate row.
8. Incoming record matching more than one quote does not link and appears under *Needs review*.
8b. Incoming record with no Solicitation # match whose normalized value equals an unkeyed quote's Code is neither auto-created nor auto-linked; it waits under *Needs review* until *Link to quote #N* or *Create new* is chosen.
9. Conflict: an incoming change older than our `partner_shared_updated_at` is ignored; a newer one is applied.
10. No echo: applying an incoming change enqueues zero outbound notices.
11. A change to a shared field enqueues exactly one notice; an unrelated edit (pricing, items, comments) enqueues none and does not move `partner_shared_updated_at`.
12. Failed deliveries retry on the back-off, then show as failed in admin; *Retry* re-queues.
13. Unshare/delete sends a `removed` notice; incoming `removed` detaches the link, hides the quote only if status is Created and unpriced, never otherwise.
14. Statuses after Award are never sent and ignored inbound.
15. Unmatched assignee uses the default assignee and sets *Needs assignment*; if the default is not configured or not found, the record is rejected and listed — never silently dropped.
16. The migration is idempotent and leaves all existing quotes unshared and unchanged.
17. Tests: PHP in `tests/php/` (auth, sharing gate, matching, conflict, echo suppression, removal rules) and Playwright in `tests/specs/` (share toggle validation, per-file share, admin card).

## Open items (blocked on the partner)

- Field list and sample payload (identifier, status, dates, documents) → defines the field mapping.
- Exact amendment / re-issue number format (suffix or identical) → defines the base-number derivation for `solicitation_key`.
- Their internal record ID present in the payload (needed for the pinned link).
- Full status list and mapping; handling of No Bid / Cancelled / Not submitted (encoded in `rfq.comments` here).
- Which of their assignees exist as users in this app (assignee email list); their bid-type value or the default we use.
- Test environment base URL, token, webhook URL, technical contact.
- Partner confirmation of the un-share rule (D) and indefinite tombstone retention.

## Out of scope

- Syncing items, pricing, providers, comments, fulfillment, invoices or any field outside the agreed shared list.
- More than one partner (schema keeps a single integration row).
- Partner logins or per-partner user accounts.
- A UI to edit the status mapping (mapping lives in code).
- Pipeline table filters/badges for partner quotes.
- Failure emails or notifications (admin failed-deliveries list only).
- Changes to the SharePoint sheet sync.
- Real-time UI push of incoming changes (SSE).

## Decisions

- Matching key: new dedicated Solicitation # field, normalized — chose over the hand-typed `email_code` because free text with no format rules causes silent duplicates and missed matches.
- Solicitation # required only when sharing — chose over always-required so unshared internal quotes are not burdened.
- Pinned partner record ID after first match — a later typo fix to the solicitation number must not orphan the link; one column, not a mapping table.
- Existing quotes link from the release date on, as records arrive — chose over a one-time match report because the existing list could be huge; instead an incoming record that equals an unkeyed quote's Code waits for one-click review, so in-flight opportunities are not duplicated.
- No test environment on our side — sharing is opt-in per quote and the integration is disabled until enabled, so testing happens in production with one or two designated test opportunities.
- Conflict rule: latest save wins — chose over field-level ownership because it is the simplest rule and both sides agreed.
- Timestamp scope: shared fields only — otherwise an unrelated pricing edit would make our copy look newer and silently discard their change.
- Link implies shared — a quote linked to a partner record is shared by definition; turning sharing off follows the removal flow.
- Webhook: light notice + fetch, HMAC-SHA256, HTTPS, retries — agreed with the partner; keeps payloads small and the fetch authoritative.
- Retry schedule 1m / 5m / 30m / 2h / 12h then failed — bounded effort; changed-since is the catch-up path.
- Stale webhook timestamp (older than 5 minutes) rejected — blocks replayed notices.
- Removals soft, tombstones kept indefinitely — storage cost is negligible and it matches the partner's soft-delete model.
- Un-share hides only untouched quotes — a priced, submitted or awarded quote must never disappear because the partner stopped sharing.
- Attachments: per-file share mark + file ID table, authenticated links — files had only a name; app-generated PDFs hold internal pricing and are never shareable.
- Status sync only up to Award — Fulfillment and Invoice are internal to us; proposed to the partner, to be confirmed.
- Incoming quotes created by a dedicated *Partner Integration* service user — the audit trail then states plainly where they came from.
- Default assignee: constant in `config.inc.php`, not a real env var — this app has no `.env` and keeps config in constants; set to the product owner for now.
- Partner settings in a single-row table with an admin-only card — follows the Shared Notification Mailbox pattern.
- Cron for dispatch and pull — reuses the droplet cron pattern of the Daily Digest; no queue infrastructure for low volume.
- Ambiguous matches are never auto-linked — a wrong link is worse than a manual review.
- Single partner only — keeps the schema and UI simple; multi-partner is a separate feature.
